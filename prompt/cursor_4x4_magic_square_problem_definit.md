# STEP 1 — Observation (관찰)

워크스페이스 `MagicSquare`에는 아직 코드나 문서가 없습니다. 따라서 아래는 **지금 대화에서 드러난 신호**와 **4×4 마방진이 일반적으로 놓이는 맥락**을 바탕으로 한 관찰입니다. (설계·구현은 하지 않습니다.)

---

## 1. 현재 우리가 해결하려는 상황은 무엇인가?

**한 사람이 4×4 격자에 1부터 16까지의 정수를 한 번씩 배치했을 때, 행·열·대각선 합이 모두 같아지는 배치를 얻고 싶어 하는 상황**입니다.

관찰 관점으로 풀면:

- **입력/출력**: 16개의 서로 다른 숫자(또는 그에 상응하는 “칸”)가 있고, 4×4 형태로 배열된 **결과 표**를 기대합니다.
- **제약**: 각 숫자는 겹치지 않고, 특정 합(마방 상수)에 맞춰 여러 방향의 합이 일치해야 합니다.
- **불확실성**: “항상 존재하는가?”, “몇 가지인가?”, “사람이 직접 채우는가, 프로그램이 제안하는가”는 아직 명시되지 않았습니다.
- **프로젝트 상태**: 저장소 이름만 있고 산출물은 없으므로, **요구를 먼저 정리한 뒤** 소프트웨어로 옮길 단계에 가깝습니다.

즉, 상황은 “퍼즐을 푼다”기보다 **규칙이 있는 4×4 배치 문제를, 앞으로 자동화·검증·표시할 대상으로 정의하려는 초기 단계**로 보입니다.

---

## 2. 왜 4×4 마방진 문제를 다루는가?

관찰 가능한 **동기 후보**는 다음과 같습니다. (어느 하나가 “정답”이라고 단정하지 않습니다.)

| 관찰 가능한 이유 | 설명 |
|------------------|------|
| **규모가 적당함** | 3×3보다 제약·패턴이 풍부하고, 5×5 이상보다는 수작업·완전 탐색·테스트가 다루기 쉽습니다. |
| **학습용 단위 문제** | 배열, 반복, 조건 검사, 백트래킹, “해 존재/유일성” 같은 알고리즘·논리 연습에 자주 쓰입니다. |
| **명확한 성공 기준** | “모든 행·열·대각 합이 같다”는 검증이 단순해, **프로그램이 맞는지 판별하기 쉽습니다**. |
| **일반화의 중간 지점** | 임의 크기 n×n으로 확장하기 전에, **고정 크기(4×4)로 요구·UI·테스트를 고정**하려는 선택일 수 있습니다. |
| **프로젝트 이름과의 정합** | 폴더명 `MagicSquare`는 이 주제를 **의도적으로** 다룰 계획임을 시사합니다. |

**아직 관찰되지 않은 것**: 수업 과제인지, 취미인지, 면접 준비인지, 라이브러리 학습인지는 대화에 없습니다. “왜 4×4인가”에 대한 답은 **나중에 요구사항 인터뷰에서 한 줄로 확정**하는 것이 좋습니다.

---

## 3. 이 문제는 어떤 학습 또는 시스템 설계 맥락에서 등장하는가?

### 학습 맥락

- **수학·퍼즐**: 조합 배치, 대칭, 마방 상수(4×4에서는 보통 34)에 대한 직관.
- **프로그래밍 입문~중급**: 2차원 배열, 중첩 루프, 불변 조건 검사.
- **알고리즘**: 완전 탐색, 백트래킹, (고급으로는) 생성 공식·패턴 기반 구성.
- **소프트웨어 품질**: “올바른 배치인지”를 **순수 함수로 검증**하는 연습 — 입력 격자 → 참/거짓.

### 시스템 설계 맥락 (아직 시스템은 없음)

문제가 소프트웨어로 가면, 보통 이런 **역할 분리** 질문이 따라옵니다(지금은 관찰만):

- **생성 vs 검증**: 사용자/엔진이 배치를 *만드는*가, *검사만* 하는가?
- **단일 해 vs 전체 해**: 하나만 보여주는가, 4×4의 여러 해를 나열하는가?
- **대화형 vs 배치**: CLI, GUI, API, 파일 입출력 중 어디에 둘 것인가?
- **신뢰 경계**: “유효한 마방진”의 정의를 코드 한곳에 둘지(도메인 규칙).

4×4는 **엔드투엔드 프로토타입**(입력 → 처리 → 출력 → 테스트)을 짧게 돌려볼기 좋은 **경계가 작은 도메인**으로 자주 선택됩니다.

## 관찰 요약 (표현 대체)

“마방진을 만든다” 대신, 지금 단계에서 보이는 상황은 대략 이렇게 말할 수 있습니다.

> **16개의 서로 다른 정수를 4×4 격자에 놓았을 때, 여러 방향의 합이 하나의 값으로 맞는지 확인하거나, 그런 배치를 찾아 제시하려는 작업을, 앞으로 프로그램으로 지원하려고 요구를 먼저 정리하고 있다.**
