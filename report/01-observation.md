# STEP 1 — Observation (관찰)

> “마방진을 만든다” 대신, **관찰 가능한 상황**으로 서술한다.

## 1. 현재 해결하려는 상황

**16개의 서로 다른 정수(1~16)를 4×4 격자에 배치했을 때, 행·열·대각선의 합이 모두 동일한 배치를 얻거나, 그런 배치가 규칙을 만족하는지 판별하려는 상황**이다.

관찰 요약:

| 관찰 항목 | 내용 |
|-----------|------|
| 대상 | 4×4 격자, 16칸, 각 칸에 1~16 중 하나 (중복 없음) |
| 규칙 | 4행, 4열, 2대각선의 합이 모두 같음 (4×4 마방 상수 = 34) |
| 기대 산출 | 규칙을 만족하는 배치를 **제시**하거나, 주어진 배치가 **만족 여부를 판별** |
| 프로젝트 상태 | `MagicSquare` 저장소명만 존재, 실행 가능한 산출물 없음 |
| 단계 | 요구를 정리한 뒤 소프트웨어로 옮기기 **이전** |

한 줄 요약:

> 16개의 서로 다른 정수를 4×4에 놓았을 때 여러 방향의 합이 하나의 값으로 맞는지 **확인**하거나, 그런 배치를 **찾아 화면에 보여 주려**고 요구를 먼저 정리하고 있다.

---

## 2. 왜 4×4 마방진을 다루는가

| 관찰 가능한 이유 | 설명 |
|------------------|------|
| 적절한 복잡도 | 3×3보다 패턴·제약이 풍부하고, 더 큰 n보다 탐색·테스트·UI가 다루기 쉬움 |
| 명확한 성공 기준 | 행·열·대각 합 일치 → 자동 검증·회귀 테스트에 유리 |
| 학습·프로토타입 | 배열, 조건 검사, 생성 알고리즘, 도메인 규칙 분리 연습에 적합 |
| 확장 전 고정 크기 | n×n 일반화 전에 4×4로 요구·화면·품질 기준을 고정하기 좋음 |
| 프로젝트 의도 | 저장소명 `MagicSquare`가 주제를 의도적으로 선택했음을 시사 |

**아직 확정되지 않은 동기**: 수업, 취미, 포트폴리오, 면접 등 구체적 목적은 별도 확인 가능.

## 3. 학습·시스템 설계 맥락

### 학습 맥락

- 수학·퍼즐: 조합 배치, 대칭, 마방 상수
- 프로그래밍: 2차원 배열, 루프, 순수 검증 함수
- 알고리즘: 생성(공식/탐색), 검증(결정적 판별)

### 시스템 설계 맥락 (관찰만)

문제가 소프트웨어가 되면 보통 다음이 갈라진다:

- **생성** vs **검증** — 별도 유스케이스·모듈 후보
- **단일 해** vs **다중 해** — UX·성능 요구에 영향
- **대화형 vs 배치** — 사용자가 칸을 채우는지, 시스템이 제안하는지
- **도메인 규칙의 단일 정의** — “유효한 4×4 마방진”을 한곳에서 정의

4×4는 엔드투엔드(입력 → 처리 → 화면 → 테스트)를 짧게 검증하기 좋은 **작은 경계 도메인**이다.
